# Supplemental Registry source controls

Run `python3 -B source-controls/run.py` from the chain-registry component-test directory after `prepare.py` and `runtime/run.py`, with Node 24.4.1 and the locked dependencies. Use a fresh evidence directory for every attempt. The runner stops at the first failure and retains compiler inputs, outputs, normal VM receipts, PC bitmaps, mappings and tool coverage. It allows one compiler or VM child at a time, a 512 MiB Node heap, at most 600 seconds per selected Core compile and 180 seconds per other compile. Cleanup targets only its own child. File-size checks are sampled acceptance limits, not an OS disk quota or a full-RSS memory limit.

The seven finite groups cover 76 stateless calls, 504 rule calls, 46 processor helper calls, 29 semantic/role reads, and two Core reads after 16 normal lifecycle setup calls. Contracts are normally created. Code identity is checked against the corresponding compiler output, with typed immutable predictions checked against actual returned/stored runtime. There is no code/storage patch, role substitution, live RPC, signer, account funding, deployment or operating authority selection. Dummy proof fields in fixed serializer vectors are not live credentials or admission evidence. Python negatives and observer failures use inert unit data only.

All 29 original source files remain in the inventory, including the empty interface. The denominator remains 1,642 original statements, with a 90% target of 1,478. Original statements are identified by source name, UTF-8 hash, node type, start and length. Test wrappers are separate sources and receive no original-source credit. Product/control builds and execution profiles stay separate; Paris role bytecode read on a Shanghai VM is a Shanghai observation. Constructor and setup PCs receive no new marker credit.

`source-observations.json` reports only this run's supplemental observations. It is not the full product coverage result. The immutable historical comparison vector records a previously independently reviewed source-entry union of 1,482/1,642 (90.26%): Paris 1,439 and Shanghai 1,482. CI checks that vector against the exact original source snapshot and recomputes its arithmetic; it does **not** authenticate the historical provenance or report those old observations as freshly executed. The historical optimized-product PC result remains 1,160/1,642 (FAIL), with a static source-map upper bound of 1,328. Supplemental source-entry QA does not replace product byte identity, behavior, authorization or security checks.

Python tool coverage covers the measurement and child-control helpers; Node reports cover the selected compiler entry, normal VM tests and observer. The outer Python orchestration/result writer is not included in that helper percentage. These tests do not establish operational readiness or completion of Registry integration.
